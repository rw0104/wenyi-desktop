# 书架与运行态 开发规划

依据 apple-design 的「设计基础八原则」与流体界面规则制定。目标是让「选择书籍」从一条路径
输入变成一间**书架**，并让运行态清楚地回答「现在在翻哪一章、还剩多少」。

## 需求

1. **书架**：未添加书籍时**保持现有拖拽区样式**；添加后以封面陈列
   - 单本：显示完整封面
   - 多本：书架式排列
2. **运行态**：显示**当前正在翻译的章节**与**剩余百分比**
3. 通过 apple-design 增加桌面端细节与动效，保持圆角与交互一致性

## 关键约束（先验证，后设计）

- **封面必须按 OPF 声明查找，不能用「最大图」启发式。** 实测目标书 `cover.jpg` 为 146 KB，
  而两幅内文插图分别为 240 KB / 158 KB —— 取最大图会把插图当封面。
- TXT / DOCX / PDF 没有封面。必须有**排版占位封面**（标题字 + 由标题派生的渐变色），
  而不是空白或破图。
- 当前有翻译在运行。**不得中断、不得杀死进程**；构建前只检查不干预。

## 数据层（Rust）

| 项 | 设计 |
|---|---|
| 书库持久化 | `library.json`：`[{input, addedAt}]`，按路径去重 |
| 多选添加 | `pick_input_files`（复数），一次可加多本 |
| 封面提取 | EPUB：`container.xml` → OPF → `properties="cover-image"` 或 `<meta name="cover">` → 图片字节 |
| 封面缓存 | `covers/<sha256(path)>` + 记录 MIME，避免每次重解压 |
| 摘要缓存 | sha256 按 `(路径, 大小, mtime)` 缓存 —— 否则轮询进度会反复整文件哈希 |
| 命令 | `list_library`（元数据，不含封面）、`book_cover`（单本封面，按需）、`add_books`、`remove_book` |

封面**不进列表接口**：列表保持轻量，封面按需加载，顺带获得「逐个浮现」的入场节奏。

## 书架 UI

- **空态**：现有拖拽区，**完全不变**（明确要求）
- **单本**：大封面（约 200×300）+ 标题 + 进度 + 操作
- **多本**：网格封面（约 132×198）+ 标题 + 细进度条 + 每行下方一道**弱化的搁板线**
  （隐喻克制，不铺木纹——apple-design：隐喻既不过于直白也不过于抽象）
- 移除按钮只从书架移除，**不删除文件**，因此不需要确认对话框（可逆操作）

## 运行态 UI

## 动效（apple-design §1 / §3 / §7 / §11 / §14）

| 交互 | 做法 | 依据 |
|---|---|---|
| 按压封面/按钮 | 指针**按下**即 `scale(0.97)`，100ms | §1 响应 |
| 悬浮封面 | `translateY(-2px)` + 加深阴影，160ms 减速曲线 | §3 可中断 |
| 封面入场 | 逐个淡入上浮，按索引错开，总时长封顶 | §7 空间一致 |
| 进度条 | `transform: scaleX()`，不用 `width` | §11 合成器友好 |
| 圆角 | 沿用既有 `--radius` / `--radius-sm` 令牌，不引入新值 | §7 工艺 |
| 减少动效 | 全部退化为淡入，去掉位移与悬浮抬升 | §14 无障碍 |

只用 `transform` / `opacity` 驱动动效；不使用长循环振荡。

## 阶段与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 数据层：多选、书库、封面提取与缓存、摘要缓存 | `cargo test` 新增用例通过 |
| P2 | 书架 UI：空态不变、单本大封面、多本网格 | 双主题截图 |
| P3 | 运行态：当前章节 + 剩余百分比 + 章节计数 | 截图确认信息层级 |
| P4 | 动效与无障碍回退 | `prefers-reduced-motion` 下无位移 |
| P5 | 构建 0.5.0、验证、提交 | 安装包产出、端到端管线仍 PASS |

## 明确不做

- **不做多本并行翻译**：引擎正文串行是为全书一致性让路；并行会让本已出现 504 的中转站更不稳。
- **不做拟物木纹**：克制隐喻，只用一道搁板线与阴影暗示「架子」。
- **不改动运行中的翻译**。
